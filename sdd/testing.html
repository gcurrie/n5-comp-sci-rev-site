Normal, Extreme & Exceptional Test Data

When we test a program, we use test data — entered as the inputs to the program. The data should try to capture a range of different scenarios: don't just test the program with one piece of data!

There are three types of test data you need to be able to use and give examples of:

Normal
Definitely within the accepted range — the program should accept and process it correctly.
Extreme
On the very edge of the accepted range (the boundaries) — but still valid and accepted.
Exceptional
Definitely invalid — the program should reject it with an error message, not crash.
Worked Example — guessing game (0 to 10)

A program picks a random number and asks the user to guess a number between 0 and 10 inclusive. Numbers outside the range should produce an error message.

TypeSuitable valuesWhy
Normal3, 5, 7Comfortably inside the range
Extreme0 and 10The minimum and maximum — still valid
Exceptional-4, 26, "ten"Outside the range or wrong type — should be rejected
Worked Example — rolling a dice

You are asked for four pieces of test data for a standard 6-sided dice: one normal, two extreme and one exceptional.

ValueType
4Normal — a value in the middle of the range
1Extreme — the minimum the dice can roll, still valid
6Extreme — the maximum the dice can roll, still valid
180Exceptional — a dice can't roll 180, totally invalid

The values 1 and 6 should still be accepted by the program — it's perfectly valid for a dice to roll a 6.

Test Tables

We write test data into a test table. Put one example in each row — don't write "anything between 1 and 9"; pick an actual value! For each row, state what you expect the program to do. Some test tables have another column for what actually happened, filled in after testing.

Error Types — Syntax, Logic & Execution

There are three types of programming error you need to know. Syntax and logic errors are made while writing the program; execution errors happen while it runs.

Syntax errors

Typing mistakes that break the rules of the language — misspellings, wrong word order, or wrong symbols. Python spots these before the program runs and reports the line number:

Python — syntax errors
priiiint("Hello")          # misspelled print
print("Hello," name)       # comma in the wrong place
range[0, 10]               # square brackets instead of range(0, 10)

Logic errors

Logic errors are trickier to spot — they don't produce error messages. The program still runs, but it doesn't do what you'd expect:

Python — a logic error
# Meant to check a rating out of 10 — but tests up to 100!
if rating >= 0 and rating <= 100:
    print("That is a rating out of 10")
Python — another logic error
name = input("What is your name?")
age = input("How old are you?")
print("Hello", age, ". You are", name, "years old.")
# Bob, aged 15, sees: "Hello 15. You are Bob years old."

Testing with appropriate test data is the best way of tracking down logic errors.

Execution errors

An execution error (or run-time error) occurs while the program is running, causing it to crash. Examples:

  • The user types in a string when the program is expecting an integer.
  • A number is not entered and the program tries to divide by 0.
  • A file that the program needs is missing or renamed.
💡
Programs that minimise the chance of execution errors are said to be robust — see the Evaluation page. Input validation prevents most execution errors.

Test Yourself

Q1 — Choose test data (3 marks)

A program accepts a percentage mark between 0 and 100 inclusive. Give one example each of normal, extreme and exceptional test data.

Marking Instructions

Normal: any value comfortably inside, e.g. 55. Extreme: 0 or 100 (the boundaries). Exceptional: e.g. -10, 150, or "abc". (1 mark each)

Q2 — Name the error type (3 marks)

Identify the type of error in each case:

  1. The program crashes when the user enters "five" instead of 5.
  2. pirnt("Total")
  3. A discount program takes 20% off instead of 10%, with no error message.
Marking Instructions

a) Execution (run-time) error. b) Syntax error. c) Logic error. (1 mark each)
