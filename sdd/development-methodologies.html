Introduction

Modern computer software is very complex — it is often worked on by teams of people who can write millions of lines of code between them! Even a small project raises tricky questions: What exactly should the program do? How should it look? How will its logic work?

The software development process is a set of steps that programming teams work through to try and reduce errors. At National 5 you need to be able to describe and implement the phases of an iterative development process within general programming problem-solving.

Key Terms

Software development process
The sequence of phases used to create software: analysis, design, implementation, testing, documentation and evaluation.
Iteration
Repeating a process. In software development, revisiting phases that have already been worked on — e.g. going back to design after testing finds a problem.
Iterative development
A development process where the phases are repeated in cycles, with the software improving on each pass.

The Software Development Process

The phases you need to know, in order:

PhaseWhat happens
AnalysisA systems analyst meets the client to determine what the program is required to do — the overall purpose and the functional requirements (exactly what steps the program must take to solve the problem).
DesignPlanning what the user interface will look like, what data should be stored, and how the program will carry out its functions (algorithm designs using structure diagrams, flowcharts or pseudocode).
ImplementationA programmer (or programming team) creates the software based on the designs, using a high-level programming language such as Python.
TestingTesters check whether the program works as expected — that it doesn't crash and that it produces correct results, using normal, extreme and exceptional test data.
DocumentationProducing supporting documents such as a user guide and technical guide.
EvaluationThe software is checked to ensure it is fit for purpose, makes efficient use of coding constructs, and is robust and readable.

A popular memory aid is "A Dance In The Dark Every Evening" — Analysis, Design, Implementation, Testing, Documentation, Evaluation.

Iteration — Why the Phases Repeat

Iteration means repeating a process. In software development, it is the term used to describe repeating or revisiting phases that may have been worked on already.

Traditionally, teams worked through the phases one after another, only moving on when the previous phase was complete. Modern teams work iteratively: the design for part of a program may be created and then implemented; any errors found during testing could lead to parts of the design and implementation changing before further testing is carried out.

ℹ️
Exam answer: if asked why development is described as iterative, say that phases are revisited/repeated when new information or errors are found — e.g. testing may reveal a problem that means the design and implementation must change.

Test Yourself

Q1 — Name the phases (2 marks)

State the six phases of an iterative development process, in order.

Marking Instructions

Analysis, Design, Implementation, Testing, Documentation, Evaluation.

Q2 — Iterative development (2 marks)

A development team describes their process as iterative. Explain what this means, using an example.

Marking Instructions

Iterative means phases are repeated or revisited (1 mark). Example: errors found during testing cause the team to return to the design and implementation phases before testing again (1 mark).
