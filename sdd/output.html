Internal Comments

The computer ignores lines that start with a #. We call these internal comments. They explain what the code does — for you, for other programmers, and for whoever marks your assignment!

Python — comments
# This program displays a welcome message
# Written by G. Currie

print("Welcome!")   # this line runs — the comments above are ignored
💡
Using internal commentary is expected at National 5 — it is one of the things that makes a program readable, and it earns marks in the assignment.

Output in Python

The print() statement displays information on the screen. In the brackets, put the message you want to print. Literal text must go inside quotation marks:

Python — printing messages
print("Hello world")
print("Welcome to National 5")

To display the contents of a variable, use its name without quotation marks — otherwise Python prints the variable's name instead of its value:

Python — printing a variable
name = "Aisha"
print(name)        # displays: Aisha
print("name")      # displays: name  (probably not what you wanted!)

In SQA reference language (used in exam papers), output is written with SEND … TO DISPLAY:

SQA Reference Language
SEND "My name is: " & name TO DISPLAY

Joining Strings — Concatenation

Concatenation means joining strings together. In Python this uses the + operator; in reference language it is the & symbol.

Python — concatenation
name = "Aisha"
print("My name is " + name)          # My name is Aisha

age = 15
print("I am " + str(age) + " years old")   # numbers must be converted with str()
⚠️
You can only concatenate strings. To join a number onto a message, convert it first with str() — e.g. "Total: " + str(total).

Test Yourself

Q1 — Predict the output (2 marks)

What is displayed when this code runs?

team = "Rovers"
print("Come on " + team)
print("team")
Marking Instructions

Line 1: Come on Rovers (1 mark). Line 2: team — because the quotation marks make it literal text, not the variable (1 mark).

Q2 — Comments (1 mark)

State one reason a programmer should include internal comments in their code.

Marking Instructions

They explain what the code does, making the program easier to read/understand/maintain for other programmers (or the original programmer returning later).
