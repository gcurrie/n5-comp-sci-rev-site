Fitness for Purpose

A program is fit for purpose if it does what it is supposed to do. The standard to judge against is the functional requirements set out in the analysis — if the program meets all of them, it is fit for purpose.

Example evaluation statements
  • "The program is fit for purpose, because it asks the user their age, and shows an error if they enter a negative number."
  • "The program is not fit for purpose, as it is only supposed to accept percentages between 0 and 100, but it accepts values outside this range."
⚠️
Don't be too kind! If it isn't fit for purpose, say so. Link your evaluation to specific requirements of the program — vague, hedging statements lose marks.

Efficient Use of Coding Constructs

Efficient code achieves its goal without unnecessary repetition. The SQA loves to show you an inefficient program and ask how to improve it. The two classic cases:

1. Repeated code → use a loop

Python — inefficient vs efficient
# Inefficient — five separate lines     # Efficient — a fixed loop
print("Hello!")                          for counter in range(5):
print("Hello!")                              print("Hello!")
print("Hello!")
print("Hello!")
print("Hello!")

2. Separate IFs → use if/elif/else

With separate if statements, every condition is checked even after the right one is found. With if / elif / else, checking stops at the first match:

Python — inefficient: three separate ifs
if age == 15:
    year = "S4"
if age == 16:
    year = "S5"
if age == 17:
    year = "S6"
Python — efficient: if / elif / else
if age == 15:
    year = "S4"
elif age == 16:
    year = "S5"
else:
    year = "S6"

Robustness

A robust program doesn't crash when the user enters exceptional data. If an age program is given a negative number, it should display an error message and ask again — not fall over.

You evaluate robustness by testing with exceptional data and asking: how does the program behave? A program that crashes is not robust; one that handles the error gracefully is — and that's exactly what you should write in an evaluation.

💡
Input validation should prevent most execution errors and make your program robust — the topics all link together!

Readability

Readability is about making your program easy for you — or other programmers after you — to read and understand. There are four techniques, and you are expected to use them all in the assignment:

Internal commentary
Comments (lines starting #) explaining the code — ignored by the computer.
Meaningful identifiers
Variable names like age or password rather than x or k.
Indentation
Code inside ifs and loops is tabbed in, making the structure clear (Python requires it!).
White space
Blank lines between sections group related code together instead of jamming it up.
Worked Example — all four techniques in one program
Python
# Ask the user to enter their name, reject if not a valid username
username = input("Please enter your username:")

if username == "admin":
    print("Welcome, admin. What would you like to do?")
else:
    print("Access denied, go away...")
  • Internal commentary — the # line at the top explains the program.
  • Meaningful identifier — username says exactly what it stores.
  • Indentation — the print statements are tabbed inside the if/else branches.
  • White space — a blank line separates the input from the selection.

Test Yourself

Q1 — The four criteria (2 marks)

State the four criteria used to evaluate a program at National 5.

Marking Instructions

Fitness for purpose; efficient use of coding constructs; robustness; readability (internal commentary, meaningful identifiers, indentation, white space). (2 marks for all four; 1 mark for two or three)

Q2 — Improve the efficiency (2 marks)

Describe how this code could be made more efficient, and name the construct you would use:

print("Line of a song")
print("Line of a song")
print("Line of a song")
print("Line of a song")
Marking Instructions

Replace the repeated print statements with a fixed loop that repeats 4 times (1 mark for identifying repetition, 1 mark for the fixed loop): for counter in range(4): print("Line of a song")

Q3 — Robustness (2 marks)

A program crashes when the user presses Enter without typing a number. Explain why the program is not robust, and describe how to fix it.

Marking Instructions

It crashes on exceptional data instead of handling it (1 mark). Add input validation — a conditional loop that shows an error message and asks again until valid input is entered (1 mark).
