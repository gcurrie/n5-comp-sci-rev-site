Introduction

In the Design stage, the purpose and requirements from analysis are turned into plans. Three things are designed:

  • what the user interface will look like — using a wireframe
  • what data the program will store — the data types and structures
  • how the program will carry out its functions — the algorithm design, using a design technique

At National 5 you must be able to describe, identify, read and understand all three design techniques — structure diagrams, flowcharts and pseudocode — and use at least one of them to design efficient solutions to a problem.

Key Terms

Wireframe
A sketch of the user interface showing the position of inputs and outputs, with annotations explaining functionality.
Structure diagram
A diagram that breaks a task into smaller chunks, read top-to-bottom and left-to-right.
Flowchart
A diagram of standard symbols and arrows showing the order of events in a program.
Pseudocode
A line-by-line plan of the program written in structured English rather than actual code.

User-Interface Design — Wireframes

A user is someone operating the program, and the user interface is the parts of the program the user interacts with. Think of Netflix: users browse films and shows, view details about each one, then select something to watch — all through the interface.

Designing the interface matters because it shows the programmer what input and output is required and how the user will interact with the program. A wireframe can be hand-drawn or made with software, and should show:

  • the positioning of each element (inputs, outputs, buttons, labels)
  • annotations explaining what each element does
Wireframe — text-based interface (weekly pay program)

For a console program, the wireframe shows each prompt the computer displays and the response the user types:

Prompt (computer)Response (user)

Enter how many hours you worked on Saturday___
Enter how many hours you worked on Sunday___
Your pay this week is __________

Structure Diagrams

A structure diagram (or structure chart) is the first design notation. We use these to break the task down into smaller chunks. A structure diagram is useful for showing the sequence of steps needed to solve the problem, and it is always read from top-to-bottom and left-to-right. You can draw them on paper or with a free online tool such as draw.io.

Structure diagram symbols

There are four different symbols that can be used on a structure diagram:

SymbolUsed for
ProcessNotes a process, such as a calculation.
LoopShows that part of the problem repeats a fixed number of times, or repeats while a condition is met.
SelectionShows that the problem may branch, depending on the conditions met.
Pre-defined processShows the use of a pre-defined function or procedure.

Showing repetition

Suppose a program that added two numbers is changed to add five numbers. Rather than drawing five separate "get number" boxes, a loop symbol is added above the repeated steps — the diagram below it is then carried out on every pass of the loop.

Flowcharts

Flowcharts are used to show the sequence of steps in a program. We read the flowchart from top-to-bottom, following the arrows. You can use a flowchart with any program, but they are especially good at clearly showing decisions and loops.

Flowchart symbols

  • A parallelogram is used for input/output.
  • A diamond is used to make a decision — decisions must have yes/no branches.
  • Flowcharts should always mark the start and end with rounded (terminal) symbols.
  • A rectangle is used for any other task, e.g. a calculation.
ℹ️
The full SQA symbol set also includes a flow line (arrow), an initialisation symbol (declaring variables or setting starting values), a pre-defined process, and an on-page connector used to split a flowchart across a page.

Loops in flowcharts

Flowcharts don't have a specific loop symbol. Instead, a loop is shown as a decision with the arrows going up/backwards.

Worked Example — Password Check Loop

If the password is not correct, the program shows an error message, and the arrow points back towards asking for the password again. The loop continues until the user enters a correct password, breaking the loop.

Pseudocode

Pseudocode is a way of planning your program line-by-line, without writing actual code. It is less rigid than a programming language, is written in English, and has no strict formatting rules — what matters is breaking the problem down into clear steps.

The design begins with the main steps (algorithm). Where a step needs more detail, it is expanded in numbered refinements — step 1 becomes 1.1, 1.2, 1.3, and so on. Each refinement should eventually translate into a line or two of actual code.

Worked Example — Swimming Pool Volume (SQA example)
Algorithm
1  Ask user to enter dimensions of a swimming pool in metres
2  Calculate volume of pool
3  Display message stating the volume of the pool
Refinement
1.1  Ask user to enter length of pool
1.2  Ask user to enter width of pool
1.3  Ask user to enter depth of pool
2.1  Volume is calculated as length * width * depth
3.1  Display "The volume of the pool is", volume
💡
Indentation can be used in pseudocode to highlight selection and repetition — just like indenting inside an if or a loop in Python.

Test Yourself

Q1 — Design techniques (2 marks)

Name the three design techniques you could use to design a program's logic at National 5, and state one thing a wireframe is used to design.

Marking Instructions

Structure diagram, flowchart, pseudocode (1 mark). A wireframe designs the user interface — the layout of the program's inputs and outputs (1 mark).

Q2 — Reading a flowchart (2 marks)

In a flowchart, state the purpose of: a) a diamond symbol; b) a parallelogram symbol.

Marking Instructions

a) A decision — the program branches depending on a condition, with yes/no branches (1 mark).
b) Input or output — data being entered or displayed (1 mark).

Q3 — Writing pseudocode (3 marks)

Write pseudocode (algorithm only) for a program that asks the user for the price of a meal, calculates a 10% tip, and displays the total cost including the tip.

Marking Instructions

One mark for each correct step in a sensible order:

Suggested answer
1  Ask the user to enter the price of the meal
2  Calculate the total as price + (price * 0.1)
3  Display the total cost including tip
