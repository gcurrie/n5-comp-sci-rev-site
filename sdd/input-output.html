Introduction

Time to actually write some Python! Every useful program does two things at its edges: it outputs information to the user, and it takes input from them. Think about Netflix or a game — the software constantly shows you things and responds to what you do. A program with no input is static; a program with no output is pointless. (Who's it for?)

This page covers the basics of both — no calculations or clever processing yet, just getting data in and out.

Key Terms

Output
Information the program displays to the user — in Python, with the print() statement.
Input
Data the user enters from the keyboard — in Python, with the input() statement.
Prompt
The message shown to the user telling them what to enter.
Casting
Converting input to the right data type with int() or float() — because everything typed at the keyboard arrives as a string.
Internal comment
A line starting with # that the computer ignores — it's there to explain the code to humans.
ℹ️
What the exam expects: input and output appear inside almost every program you'll read, explain and write — and in reference language questions they look like RECEIVE … FROM KEYBOARD and SEND … TO DISPLAY.

Output with print()

The print() statement displays information on screen. Put the message you want inside the brackets — literal text goes in quotation marks:

Python — printing messages
print("Hello world")
print("Welcome to National 5")

To display what's inside a variable, use its name without quotation marks. With quotes, Python prints the literal text; without, it prints the contents:

Python — printing a variable
name = "Aisha"
print(name)        # displays: Aisha
print("name")      # displays: name  (probably not what you wanted!)

In SQA reference language — which is how output appears in exam papers — the same idea is written as:

SQA Reference Language
SEND "My name is: " & name TO DISPLAY

Internal Comments

Any line starting with a # is an internal comment. The computer ignores these lines completely (na na na na, can't hear you) — they exist to explain the code to whoever reads it: you, another programmer, or the person marking your assignment.

Python — comments
# This program displays a welcome message
# Written by G. Currie

print("Welcome!")   # this line runs — the comments are skipped
💡
Get into the habit now: comment every program you write. Internal commentary is one of the four things that make code readable — and readability earns marks. More on the Evaluation page.

User Input with input()

When you want the user to enter data, use an input statement. The message in the brackets is the prompt — it tells the user what you're asking for:

Python — inputting strings
# Enter some data from the keyboard
name = input("Please enter your name: ")
title = input("Enter book title: ")
author = input("Enter book author: ")

Whatever the user types gets stored in the variable on the left. You'll use input() in almost every program you write this year.

💡
Write helpful prompts! input("Enter number: ") — what number? Of what? A clear prompt like "Enter the number of tickets (1-6): " makes your program far easier to use.

Inputting Numbers — Casting

Here's the catch: everything typed at the keyboard arrives as a string. If the user types 15, your program receives the text "15" — which you can't do maths with. Before calculating, you must convert (cast) the input to the right data type:

Python — casting input
# Strings need no conversion
name = input("Please enter your name: ")

# For an integer (whole number), wrap the input in int( )
age = int(input("Enter your age: "))

# For a real number (decimals), wrap it in float( )
price = float(input("Enter the price: "))

Match the cast to the data type you identified back in analysis: whole number → int(), decimal → float(), text → no cast needed.

⚠️
Forgetting int() or float() is one of the most common N5 mistakes — the program crashes (or behaves very strangely) the moment you try a calculation. If your maths "isn't working", check your casts first.

In reference language, the data type is shown in brackets instead:

SQA Reference Language
RECEIVE name FROM (STRING) KEYBOARD
RECEIVE age FROM (INTEGER) KEYBOARD
RECEIVE height FROM (REAL) KEYBOARD

Putting It Together

A complete (if nosy) little program using everything on this page — comments, inputs with the right casts, and outputs:

Python — inputs and outputs, no processing
# Ask the user about themselves
name = input("Please enter your name: ")
age = int(input("Please enter your age: "))
height = float(input("Please enter your height in metres: "))

# Play it all back to them
print("Hello " + name)
print(age)
print(height)

Notice there's no processing here at all — data in, data straight back out. The interesting bit in the middle (doing something with the data) starts on the Calculations page.
