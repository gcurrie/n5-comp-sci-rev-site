Analysis — Purpose

The Analysis stage investigates what the software must do. Questions asked at this stage include:

  • What does the client want the software to do?
  • Who will use the software?
  • What are the inputs, processes and outputs?
  • What hardware will the software run on?

A systems analyst gathers this information by:

  • visiting and observing the client's workplace
  • interviewing the client's employees
  • studying documentation
  • issuing questionnaires

The result of the analysis stage is a document called the software specification. It sets out exactly what the software is required to do. Once the client reviews and agrees to it, both parties sign it, and it becomes a legally binding contract that can be used to settle disputes.

ℹ️
At National 5 you won't write a full software specification — but you must be able to read a problem description and identify its purpose and functional requirements.

Key Terms

Purpose
A plain-language statement of what the program is for — what it will do, and for whom.
Functional requirements
The inputs, processes and outputs a program must have to solve the problem.
Inputs
The data that must be entered into the program by the user.
Processes
The calculations carried out, or new data generated, by the program.
Outputs
The results and messages the program displays to the user.
Software specification
The document produced at the end of analysis stating exactly what the software must do — signed by both parties as a legally binding agreement.

Functional Requirements — Inputs, Processes & Outputs

Once the purpose of a program has been defined, the analysis looks at its individual functions. These functional requirements are agreed with the client and are organised into three categories:

CategoryMeaningSpot it in a question by…
InputsData gathered from the user"the user enters…", "asks for…"
ProcessesCalculations or new data the program generates"calculates…", "checks…", "counts…"
OutputsResults and messages displayed"displays…", "shows a message…"
💡
Read the problem specification carefully and pick out the key pieces of information the program will need. Highlight the verbs — enter, calculate, display — they signpost inputs, processes and outputs.

Worked Examples

Exam Scores Program

Problem: A program is needed to help a student work out their total score across three exams. The student should enter their Physics, Computing and Maths marks. The program should add the scores together and display the total with a suitable message.

InputsThe three exam marks (Physics, Computing, Maths)
ProcessesAdd the three scores together
OutputsDisplay the total score with a message
Edinburgh Castle Program

Problem: Edinburgh Castle needs a program for its ticket desk. The employee enters the number of adult tickets and the number of child tickets sold for a tour group. The program calculates the total cost of the group (adult tickets cost £19.50, child tickets cost £11.50) and displays the total cost of the booking.

InputsNumber of adult tickets, number of child tickets
ProcessesCalculate the total cost (adults × 19.50 + children × 11.50)
OutputsDisplay the total cost of the booking

Test Yourself

Q1 — Functional Requirements (3 marks)

A leisure centre needs a program for its café. The user enters the price of each of the four items a customer buys. The program calculates the total cost, applies a 10% member discount, and displays the final amount due.

Identify one input, one process and one output of this program.

Marking Instructions

One mark each for a valid input, process and output:

Input: the price of each item bought (four prices).
Process: calculate the total cost / apply the 10% discount.
Output: display the final amount due.

Q2 — Purpose (1 mark)

State the purpose of the leisure centre café program described in Q1.

Marking Instructions

To calculate the total cost of a customer's café order, including the member discount, and display the amount due.
