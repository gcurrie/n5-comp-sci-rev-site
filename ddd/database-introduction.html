Introduction

You have almost certainly used a dozen databases already today — you just never saw one. Every time you searched for a song, checked a bus time, logged into a game, scanned something at a self-checkout or scrolled a shop for trainers in your size, an app went away and looked something up for you. The thing it looked in was a database.

A database is a collection of information about a particular topic, stored in a structured way so that a computer can find, sort and update it quickly. That word "structured" is what separates a database from a pile of notes in your bag: every piece of information is kept in a strict, predictable pattern, so the computer always knows exactly where to look.

That is also why it can be so fast. A streaming service holding a hundred million songs can find the one you typed in a fraction of a second — not because the computer reads all hundred million, but because the information was organised before you ever went looking.

💡
An app is only the window onto the data — the database is what's behind the glass. The screen you swipe is not where the information lives, which is why your account, your playlists and your messages are all still there when you log in on a different phone.

Key Terms

Database
A structured collection of information about a particular topic, stored so a computer can search, sort and update it quickly.
Field
A single piece of information about a person or thing — e.g. a pupil's name, date of birth or address. A field is also known as an attribute.
Record
A collection of fields about one particular person or thing — e.g. one record for each pupil in a school.
Table
A collection of records on a particular topic — e.g. a table containing a record for every pupil in the school.
Attribute type
What kind of data a field is allowed to hold — text, number, date, time or Boolean.
ℹ️
What the exam expects: you should be able to describe and identify the terms field (attribute), record and table, and select and justify a suitable attribute type for a given piece of data.

Databases You Already Use

Databases feel abstract until you spot the ones you use without thinking. In every case below, the pattern is identical: there is a long list of things, and the same set of questions is asked about every single one of them.

The app or serviceOne entry holds……and what it stores about it
A music streaming appone songtitle, artist, album, length, release date
Your school's systemone pupilforename, surname, date of birth, year group, registration class
An online clothes shopone item of stockdescription, price, size, colour, number left

Look down the middle column. Every one is a single, countable thing — one song, one pupil, one product. That is the idea a database is built on, and it is the idea the next section gives a proper name to.

What people actually do with them

Whatever the app, almost everything you do with it comes down to four jobs:

  • Search — find one thing among millions, by typing part of what you want.
  • Sort — put them in an order: price low to high, newest first, A to Z.
  • Filter — cut the list down to the ones that matter: only size 8, only in stock, only today's trains.
  • Add, change and remove — a new follower appears, you change your username, you delete a photo.

Every one of those is you giving the database an instruction through a nice-looking screen. Later in this topic you will write those same instructions yourself, in a language called SQL — so the search box you have used a thousand times is about to become something you can build.

Example — the self-checkout, step by step

You scan a bottle of juice. The barcode is just a number, and the till has no idea what it means — so it goes and looks that number up. Back comes the entry stored for that one product: the name to print on your receipt, the price to add to your total, and whether it needs staff approval. The screen updates in well under a second.

Nothing on the screen mentioned a database, and you never saw the list of thousands of products it searched. That is what almost every database looks like from the outside: invisible, and doing all the work.

Databases — Key Terminology

Now the proper names. That "one countable thing" from the last section — one song, one pupil, one product — is called a record, and databases are organised into fields, records and tables:

Field
A single piece of information about a person or thing — e.g. a pupil's name, date of birth or address. A field is also known as an attribute.
Record
A collection of fields about one particular person or thing — e.g. one record for each pupil in a school.
Table
A collection of records on a particular topic — e.g. a table containing a record for every pupil in the school.
Example — a school pupil table
ForenameSurnameDateOfBirthYearGroup
AishaKhan04/02/2010S4
CallumReid19/09/2009S5
IonaMurray30/06/2010S4

Each column is a field (attribute); each row is a record; the whole thing is a table.

It is worth checking you can say that the other way round too, because the exam asks it both ways: Aisha Khan's whole row is a record; the DateOfBirth column is a field; 04/02/2010 is one piece of data sitting where a record and a field meet. Swap "field" and "record" over and you lose the mark, so it is worth a minute to make it stick.

Field / Attribute Types

Each attribute in a database must be assigned a type, which specifies what sort of data the field will hold. The National 5 attribute types are:

TypeStoresExample
TextLetters, numbers and symbols"Aisha", "KA7 2RG"
NumberNumeric values15, 2.49
DateA calendar date04/02/2010
TimeA time of day09:15
BooleanOnly TRUE or FALSEhasPaid = TRUE
⚠️
In MS Access, Date and Time fields are called Date/Time and Boolean fields are called Yes/No. You must not use the MS Access names when designing your database or answering exam questions — use the SQA types above.

Test Yourself

Q1 — Terminology (3 marks)

A vet's database stores information about pets. Match the terms field, record and table to: a) all the information about one pet; b) all of the pets; c) a pet's name.

Marking Instructions

a) Record. b) Table. c) Field (attribute). (1 mark each)

Q2 — Attribute types (3 marks)

State the most suitable attribute type for: a) a pet's appointment time; b) whether its vaccinations are up to date; c) the owner's phone number "07700 900123".

Marking Instructions

a) Time. b) Boolean. c) Text — the leading 0 and space would be lost if stored as a number! (1 mark each)
