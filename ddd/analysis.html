End-User Requirements

In the analysis stage of a database problem you must be able to identify two kinds of requirement. End-user requirements describe what the people using the database want to accomplish with it.

Example — youth club (2019 exam context)
  • The club leaders need to add new activities.
  • The club leaders need to identify adults with first aid qualifications.
  • The club leaders need to find the activities members are registered for.
  • The club leaders need to view all members listed alphabetically.
💡
Answer format: start with the person — "The club leader needs…", "The shop staff need…", "The headteacher needs…"

Functional Requirements

Functional requirements specify what the database must do to meet the end-users' needs — the entities and attributes (tables and fields) it needs, and the queries required to search and sort the data.

Example — youth club functional requirements
  • The database needs a table storing leader details, including first aid qualification status.
  • The database needs tables for members and activities.
  • The database needs a query to display members sorted alphabetically by town.
💡
Answer format: start with the database — "The database needs a table about…", "The database needs a query to…"

The UK GDPR

The General Data Protection Regulation (UK GDPR) is a law covering how your data is stored and used (it replaced the Data Protection Act terminology in 2018). Some key terms:

Data subject
The person whose data is stored.
Data controller
The person/organisation controlling how the data is used.
Declared purpose
The stated reason the data was collected.

The implications for individuals and businesses are that data must be:

  1. processed lawfully, fairly and in a transparent manner in relation to individuals
  2. used for the declared purpose only
  3. limited to the data needed for the declared purpose
  4. accurate
  5. not kept for longer than necessary
  6. held securely
Example — GDPR applied to the youth club
  • The club should collect only the data it needs for membership.
  • The data may be used only for running the club — not shared or sold without consent.
  • When a member leaves, their data should be deleted — it can't be kept longer than necessary.
  • Member data must be held securely.
ℹ️
Exam questions usually ask you to identify two implications in the context of the scenario — knowing two or three well is enough. (GDPR officially sits in the design part of the course spec, but it fits naturally alongside analysis.)

Test Yourself

Q1 — Requirements (2 marks)

A gym is having a database created. State one end-user requirement and one functional requirement for a system that lets staff find members whose membership has expired.

Marking Instructions

End-user: the gym staff need to identify members whose membership has expired (1 mark). Functional: the database needs a query to display members where the expiry date is before today's date / a table storing membership expiry dates (1 mark).

Q2 — GDPR (2 marks)

The gym stores members' personal details. Describe two implications of the UK GDPR for the gym.

Marking Instructions

Any two of: only collect the data needed for membership; use it only for the declared purpose; keep it accurate; delete it when no longer needed (e.g. when a member leaves); hold it securely; process it lawfully, fairly and transparently. (1 mark each)
